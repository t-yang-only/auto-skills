# 矛盾分析法

> 研究任何过程，如果是存在着两个以上矛盾的复杂过程的话，就要用全力找出它的主要矛盾。捉住了这个主要矛盾，一切问题就迎刃而解了。

## 该用 / 不该用

该用：

- 问题复杂，不知从哪下手
- 多个问题互相牵制，解决一个牵动另一个
- 反复出现的故障、反复失败的尝试，怀疑没打中根源
- 需要在多个"都重要"的事里判断哪个最重要

不该用：

- 任务是单维度的直接执行
- 用户已经指定方案，只需实现
- 问题属于已知模式，直接套用已验证方案更快

## 操作规程

先保证事实基础：矛盾清单里每一项都要能指向调查得到的现象，不能凭印象。**事实不够先做 `investigation-first`。**

1. **列矛盾清单**：`[A] vs [B]` 格式，写清两个对立面各自要什么。透过现象看内在张力，不只列表面症状。
2. **判定主要矛盾**：标 ⭐ 并给理由。三个检验：
   - **因果**：解决了它，别的矛盾是否随之缓解？
   - **根源**：它是不是别的矛盾的来源？
   - **阶段**：它是否处于当前阶段的中心？
3. **找主要方面**：主要矛盾内部，哪一方当前占支配地位？这决定问题现在的性质。
4. **定性质**：
   - **对抗性**（根本冲突，不能兼得）→ 明确取舍，果断二选一
   - **非对抗性**（共同目标下的分歧）→ 先找共同点，再通过讨论解决分歧
5. **选处理方向**，写出「接下来我将……」：
   - 技术性矛盾 → 形成假说，交 `verification-before-completion` 验证
   - 资源性矛盾 → 集中解决主要矛盾，其余显式推迟
   - 多目标平衡 → `writing-plans`
6. **设监控提示**：哪个次要矛盾可能上升为主要矛盾？哪个非对抗性矛盾可能因处理不当激化？

## 输出模板

```text
矛盾清单：
- [A] vs [B]：……
- ⭐ [C] vs [D]：主要矛盾。理由：解决了它，[X]、[Y] 随之缓解
  - 主要方面：当前 [C / D] 占支配地位，因为 ……
  - 性质：对抗性 / 非对抗性
接下来我将：……
⚠️ 需监控：[次要矛盾] 是否上升为主要矛盾；[矛盾] 是否激化
```

## 与 auto-skills 台账的结合

矛盾分析的结论**直接决定任务怎么拆**：

- **主要矛盾 = 当前该认领的那一个任务**。列了五个"都要做"却同时认领，等于没有主要矛盾
- 认领时把"主要矛盾是什么、哪些显式推迟"写进任务描述 —— 否则 reviewer 无法判断"没做的那些"是有意推迟还是漏了
- 解决过程中主次对调是正常的：**发现主要矛盾变了，就更新台账**，不要抱着旧判断继续做完

## 纪律

- **禁止只输出分析不给结论** —— 六项（清单 / 主要矛盾 / 理由 / 主要方面 / 性质 / 下一步）缺一不可
- **主要矛盾只能有一个** —— 列出两个"都是主要"的，说明分析还没做完
- **禁止一刀切** —— 对具体的事物作具体的分析，不套模板
- **矛盾会转化** —— 解决过程中主次可能对调，随时更新
- **不能拿"都很重要"当结论** —— 那是没分析的托词

## 交接

- 主要矛盾确定 → 需要集中资源时显式推迟次要项；需要验证假说时走 `verification-before-completion`
- 处理对抗性矛盾前需要更多事实 → `investigation-first`
- 矛盾在"该改什么"上 → `brainstorming` 展开候选方案

## 完成判据

- 矛盾清单里每一项都能指向具体现象（不是凭印象列的）
- 主要矛盾**只有一个**，且有因果/根源/阶段三检验中的至少两条支撑
- 给出了"接下来我将……"，且能看出次要矛盾被如何处置（推迟/并行/放弃）
- 写明了需要监控的转化风险
