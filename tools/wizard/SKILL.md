# 人工步骤向导

**wizard = 一个 bash 脚本，带人逐步走完一个手工流程** —— 那个流程手工做很烦、每次给 AI 讲一遍更烦。

它逐段打开 URL、说清点什么、复制什么、捕获值、写到该去的地方（`.env`、GitHub secrets）、每步确认、显示还剩几段。

**什么时候不用它**：agent 自己能做的步骤不要做成向导。向导只用于**只有人能做**的部分 —— 登录控制台、开通服务、拿密钥、做不可逆确认。

## 四步

### 1. 划定流程

**先读仓库，别冷问**：

- 配置类：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置、`.github/workflows/*`。**每个 `secrets.*` / `vars.*` 引用都是向导必须产出的一个值**。
- 迁移类：当前状态、目标状态、两者之间不可逆的动作。

然后给用户看**有序的阶段列表**和每段产出的值，让他增删调序。

**完成判据**：每段都有名字且有序；每个被捕获的值，你都知道 (a) 人从哪拿到它、(b) 它写到哪（`.env` / GitHub secret / 两者 / 哪里都不写——有些段是纯动作）、(c) 它是机密（隐藏输入）还是公开。

### 2. 映射每段的路径

每段写出人走的确切路径：打开哪个 URL、在那里做什么、值显示在哪、填进哪个变量。例如「控制台 → Developers → API keys → Reveal test key → 复制」。

**你不知道当前 UI 或确切命令时，说出来并去查** —— 编造不存在的步骤会让用户在第三步就卡死。

**完成判据**：每段都能落到一个陌生人可照做的具体指令。

### 3. 编写向导

按依赖顺序一段一段写，用库里的 helper（`stage` / `say` / `open_url` / `ask` / `ask_secret` / `write_env` / `set_secret`）。

守住模板定下的标准：**先打开 URL 再问值**；机密一律用 `ask_secret`；每个要持久化的值都走 `write_env`；只把 CI 真正需要的写进 `set_secret`；任何不可逆动作前先 `confirm`。每段清屏、只显示当前步 —— **一段只做一件事**，别让用户需要的内容被刷走。

**完成判据**：`TOTAL_STAGES` 等于实际段数；每段是单一聚焦任务。

### 4. 验证与交接

- `bash -n <脚本>`；有 shellcheck 就跑一遍
- `chmod +x`
- **不要自己端到端跑** —— 它会开浏览器、阻塞在人工输入上。改**静态追踪**：第 1 步列出的每个值都被捕获且落到它该去的地方；每个 `set_secret` 的名字与 CI 里的 `secrets.*` 引用**逐字一致**
- 告诉用户怎么跑。若是可重复路径，提交并让 README 链过去

**完成判据**：语法检查通过；每个值都有"捕获 → 落点"的静态证据；`set_secret` 名字与 CI 引用逐个对上。

## 反合理化表

| 借口 | 现实 |
|---|---|
| "先随便写几步，用户会自己调整" | 用户要的是照做，不是帮你调试向导 |
| "这个控制台我知道长什么样" | UI 会改版。不确定就查或问，别编 |
| "值先写进 README，用户自己复制" | 那正是向导要消灭的步骤 |
| "我跑一遍试试" | 它阻塞在人工输入上，你跑不完 —— 静态追踪才对 |
| "一次性的，不用提交" | 对，除非用户想要可重复路径。默认不提交 |

## 完成判据

- 阶段有序，每段的产出值有明确来源与落点
- 机密用隐藏输入；不可逆动作前有确认
- `bash -n` 通过；`set_secret` 名字与 CI 引用逐字一致
- 用户知道怎么运行它，以及它是不是可重复路径
