# 本机运维层（Windows 计划任务）

> 这一层**不在仓库里**（脚本在家目录），但决定「仓库改动有没有真的落到各 AI 工具、备份有没有按时跑」。
> 换机器或排障时，只看仓库会完全看不到它们的存亡，因此在此登记。

## 两个计划任务

| 任务名 | 脚本 | 触发 | 作用 |
|---|---|---|---|
| `AutoSkills-Deploy-Watch` | `~\.local\bin\auto-skills-deploy-watch.ps1` | 每日 09:00 与 21:00 | 检查六个 harness 根与快照是否漂移，**只有漂移才**推 ServerChan |
| `AutoSkills-Backup` | `~\.local\bin\auto-skills-backup.ps1` | 每日 03:30 | 打工作树 zip + git bundle，并按保留策略清理旧份 |

两者都用**真实 pwsh 绝对路径**作为 Execute：

```
%LOCALAPPDATA%\Microsoft\WindowsApps\Microsoft.PowerShell_8wekyb3d8bbwe\pwsh.exe
```

**不要**改成 `pwsh.exe` 这种相对名 —— PATH 上会命中 `%LOCALAPPDATA%\Microsoft\WindowsApps\pwsh.exe`（Store 应用别名，0 字节），任务报 `0x80070002` 且**静默失败**（本项目已踩过两次：`AgentNode-Watchdog`、`LLM-Wiki-Local-Rebuild`）。

## 备份脚本的三条纪律

1. **必须包含 `.evolution`**。它是私有配置覆盖层、私有技能区、通知密钥与用户画像所在。早期备份曾用 `/XD .evolution` 排除它，后来 `build_dist` 误用 `rd /s` 跟随 Junction 删掉真源 `.evolution` 时，最近的几份备份都救不回来，只能靠更早那份。
   只排除三项：`.git`、`__pycache__`、`.dist`（快照，可重建）；以及两个纯瞬时状态文件 `db_health.json`（熔断状态）、`db_cleanup.json`（清理节流）—— 备份在熔断打开期间执行会让恢复后白等一个冷却期。
2. **zip 与 bundle 互补，缺一不可**。zip 只含工作树（且不含 `.git`），能直接解压看文件；bundle 含完整提交历史，能 `git clone` 回来。只有 zip 时恢复不出历史。
   校验 bundle 必须在**仓库内**执行：`git -C <repo> bundle verify <file>`；在备份目录跑会报 `need a repository to verify a bundle`（实测踩过）。
3. **必须有保留策略**。否则每天跑只增不减（实测累积到 64 份 / 196.7 MB）。现为 full / git 各留最近 10 份，不动早期的手工 `auto-skills-snapshot-*`（那批不再增长）。

## 改脚本后必须做的两件事

1. **保住 BOM**。`.ps1` 必须 UTF-8 **带 BOM**，否则 PowerShell 5.1 按 GBK 解码，中文字符串吞引号、直接 ParserError。
   实测：用编辑器/补丁工具改完会**丢掉 BOM**，必须复核并补回：
   ```powershell
   $t = [System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
   [System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($true)))
   ```
2. **手动实跑一次并看退出码**。计划任务要到下一个触发点才执行，`LastTaskResult` 在此之前是 `267011`（`0x00041303` = `SCHED_S_TASK_HAS_NOT_RUN`，"从未运行"），不代表任何成败。
   ```powershell
   & "%LOCALAPPDATA%\Microsoft\WindowsApps\Microsoft.PowerShell_8wekyb3d8bbwe\pwsh.exe" `
     -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\.local\bin\auto-skills-backup.ps1"
   $LASTEXITCODE   # 必须是 0
   ```
   注意 `robocopy` 成功时退出码是 **1**（不是 0），所以脚本不能让它泄漏成最终退出码。

## 恢复演练（未验证过的备份不算备份）

```powershell
# 1) 历史：从 bundle 克隆，提交数与 HEAD 都要对得上
git clone <备份目录>\auto-skills-git-<ts>.bundle $env:TEMP\chk
git -C $env:TEMP\chk rev-list --count HEAD

# 2) 工作树：解 zip，确认 .evolution 与密钥文件在、技能数对
Expand-Archive <备份目录>\auto-skills-full-<ts>.zip $env:TEMP\chk2
Test-Path $env:TEMP\chk2\.evolution\secrets\notify_channels.json
```

2026-09-22 实演结果：bundle 克隆出 **60 提交**、HEAD `f88985d` 与源一致；zip 解出 **35 技能** + `.evolution`（含 `config.yaml` 与 `notify_channels.json`）。

## 排障：任务"跑了但什么都没发生"

`LastTaskResult` 的常见值：

- `0` —— 成功。
- `267011`（`0x00041303`）—— **从未运行**（还没到第一个触发点），不是失败。
- `2147942402`（`0x80070002`）—— `ERROR_FILE_NOT_FOUND`，几乎总是 Execute 写了相对名（见上文）。
- `1` —— 脚本自己 `exit 1`。本项目里 `1` 通常来自**内容错误**（如 YAML 解析失败）而非脚本本身坏了，先看脚本日志。
